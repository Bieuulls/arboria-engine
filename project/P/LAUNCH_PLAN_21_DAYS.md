# 21-Day Publication and Contributor Recruitment Plan

**Mission:** attract serious contributors and turn the ARBORIA repository into an active, credible place for technical collaboration.

**Principle:** quality over volume. Never spam communities or pretend a test has been performed. Each post should link to a useful artifact and end with one clear contribution request.

## Prerequisites (before Day 1)

- Select a public license and verify rights to code/assets.
- Confirm a public repo URL, clean build instructions, Discussions, issue templates and a private security-reporting route.
- Prepare 1–2 real screenshots or clips, one reproducible benchmark and a clear "Known limitations" issue.
- Open at least five real scoped issues across docs, testing, GPU and import pipeline.
- Configure GitHub Pages landing page if desired and confirm every link works.

## Weekly operating cadence

- **Monday:** publish verified status, blockers and top 3 help-wanted issues.
- **Wednesday:** release a technical deep dive with a real reproduction case.
- **Friday:** publish evidence-backed improvement or a negative result.
- **Weekend:** welcome newcomers, review PRs, thank contributors, prune stale tasks.

## What to measure

- **Contributors:** meaningful issues, PRs, repeat contributors and successful onboarding.
- **Engineering:** reproducible failures fixed, cross-machine tests, accepted optimizations.
- **Community:** useful technical discussions, retention, time to helpful response.
- **Reach:** repository visits/stars can be tracked, but are secondary to actual contributions.

## Rules for authenticity

- Never claim a feature is complete based only on an internal report.
- Never claim community support or endorsements you do not have.
- Use only current captures and measured results.
- Never mass-tag developers or send unsolicited bulk messages.
- Credit contributors with permission and preserve third-party rights.
- Make every announcement include at least one useful technical link.
